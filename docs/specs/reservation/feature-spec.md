## Feature Spec

### 확정된 정보
- Inputs:
  - 예약 생성 입력: `shopId`, `staffId`, `date`, `time`, `requirements`, `imageUrls`, `menuSelections`
  - 예약 확정 입력: `durationMinutes`, 점주 전달 메시지
  - 예약 거절 입력: 거절 사유
  - 예약 취소 입력: 취소 사유
  - 예약 수정 입력: `date`, `time`, `staffId`, `requirements`, 이미지, 메뉴, 입력값
- Processing Flow:
  - 고객은 `availability` 기준으로 예약 가능한 슬롯에 대해서만 예약 요청을 생성한다.
  - 예약은 `PENDING` 상태로 생성된다.
  - 점주는 `PENDING` 예약을 확정하거나 거절할 수 있다.
  - 고객과 점주는 정책에 따라 예약을 취소할 수 있다.
  - 점주는 `PENDING`, `CONFIRMED` 예약을 수정할 수 있다.
  - `CONFIRMED` 예약의 시간 관련 정보가 바뀌면 점유를 재계산한다.
- Business Rules:
  - 동일 슬롯의 `PENDING` 중복 접수는 허용한다.
  - 예약 생성 시 아래 조건을 모두 만족해야 한다.
    - 과거 날짜/시간 아님
    - 예약 가능 기간 내부
    - 최소 리드타임 충족
    - 휴무일 아님
    - 직원 운영시간 내부
    - `availability` 기준 예약 가능 슬롯
  - `requirements`는 저장 대상이며 상세 조회에는 포함, 목록 조회에는 제외한다.
  - 메뉴와 입력값은 예약 시점 스냅샷으로 저장한다.
  - 고객은 예약일 전날 `23:59:59`까지 취소 가능하다.
  - 예약일 `00:00`부터 고객 셀프 취소는 불가하다.
  - 점주는 운영상 언제든 취소 가능하다.
  - `CONFIRMED` 취소 시 점유 블록은 즉시 해제한다.
  - `CANCELED`에는 취소 메타데이터를 보관한다.
  - `NO_SHOW`는 연락 없이 미방문한 후속 확장 상태다.
- Permissions:
  - 고객: 예약 생성, 자신의 예약 목록/상세 조회, 정책 내 취소
  - 점주: 자신의 샵 예약 목록/상세 조회, 확정, 거절, 취소, 수정
- Edge Cases:
  - 동일 슬롯에 여러 `PENDING`이 존재할 수 있다.
  - 시간 블록 충돌 시 확정 또는 확정 상태 수정은 실패하고 기존 상태를 유지한다.
  - 당일 고객이 연락했고 점주가 슬롯을 비우는 경우는 `CANCELED`로 처리한다.
  - 연락 없이 방문하지 않은 경우는 향후 `NO_SHOW`로 처리한다.

### 열린 질문
- 없음.

### 가정
- `COMPLETED`, `NO_SHOW`는 이번 범위에 구현하지 않는다.
