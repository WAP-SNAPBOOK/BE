## 논의 1: 슬롯 생성 방식

**질문**: 물리적 슬롯 vs 계산 기반?

**논의**:
- 물리적 슬롯: slot 테이블에 row 미리 생성. `reservation_time_blocks`와 이중 관리 리스크, 배치 필요.
- 계산 기반: 규칙만 저장, 조회 시 실시간 계산. 이중 소스 제거, 설정 변경 즉시 반영.

**합의**: 계산 기반. 기존 `slots` 테이블은 사용하지 않고 있었으므로 무시.

---

## 논의 2: 운영 시간 구조

**질문**: 하루에 복수 블록(휴게시간) 필요한가?

**합의**: 필요함. 같은 요일에 복수 row로 표현 (예: 10:00-13:00, 14:00-19:00).

---

## 논의 3: 운영 시간과 휴무일의 역할 구분

**질문**: "일요일 안 해요"를 운영 시간에서 표현할 건지 휴무일 테이블에서 표현할 건지?

**논의**:
- 방법 A: 운영 시간에 해당 요일 row를 안 넣는다 = 안 함
- 방법 B: 운영 시간에도 넣고, 휴무일에도 넣는다

**합의**: 방법 A. 운영 시간 = 기본 스케줄 (없는 요일은 안 함), 휴무일 = 기본 스케줄의 예외.

---

## 논의 4: 격주 휴무 기준

**질문**: "격주 토요일 휴무"에서 어느 주가 쉬는 주인지 어떻게 판단하는가?

**대안**:
- 기준 날짜 저장: "2026-02-15(토)부터 격주"
- 짝수주/홀수주: 연도 주차 기준

**합의**: 기준 날짜 방식. 점주 입장에서 "이번 주 토요일부터 격주"가 직관적.

---

## 논의 5: 공휴일 처리

**질문**: 공휴일 데이터를 어디서 가져오는가?

**대안**:
- A: 서버 정적 데이터 (수동 관리)
- B: 외부 API (자동)

**합의**: A (정적 데이터)로 시작. 필요시 API 전환.

---

## 논의 6: 예약 가능 기간 / 마감 시간

**질문**: 고정값 vs 점주 설정 가능?

**합의**:
- 예약 가능 기간: 기본 30일, 점주 설정 가능 (`booking_window_days`)
- 예약 마감: 기본 60분 전, 점주 설정 가능 (`min_booking_lead_minutes`)

---

## 논의 7: 직원별 운영 시간

**질문**: 모든 직원이 매장 시간을 따르는가, 개별 설정 가능한가?

**합의**: 개별 설정 가능. 매장 기본값 + 직원별 오버라이드 방식.

---

## 논의 8: 직원 오버라이드 방식

**질문**: 전체 대체 vs 요일별 오버라이드?

**논의**:
- 전체 대체: row가 하나라도 있으면 직원 전체 스케줄 대체. 단순하지만 불필요한 반복 입력.
- 요일별 오버라이드: 해당 요일 row만 오버라이드, 나머지 매장 fallback. `is_off` 플래그 필요.

**합의**: 요일별 오버라이드. 매장 범위 안에서 조금씩 다른 현실에 적합. 직원 시간은 매장 범위 내 축소만 가능.

---

## 논의 9: 직원 개인 휴무

**질문**: 직원별 휴무 (예: "직원 A는 매주 수요일 쉼") 지원하는가?

**합의**: 제외. 매장 레벨 휴무만 관리.

---

## 논의 10: 예약 간격 범위

**질문**: 매장 단위 통일 vs 직원별 설정?

**합의**: 매장 단위 통일 (30분 or 60분).

---

## 논의 11: schedule_type 역할

**질문**: `schedule_type` (매일 같아요/평일-주말/요일별)이 저장 구조에 영향을 주는가?

**논의**:
- 저장은 항상 요일별 row. "매일 같아요"를 선택해도 월~일 7개 동일 row 저장.
- `schedule_type`은 프론트 UI 렌더링 힌트 + 요청 해석용.
- 프론트가 "매일 같아요" 선택 시 시간 1개를 보내면 백엔드가 7개 row로 풀어서 저장.

**합의**: 위 설명 그대로. `schedule_type` 변경 시 기존 `shop_operating_times` 전부 삭제 후 교체.

---

## 논의 12: 운영 시간 종료 시각 의미

**질문**: 운영 시간의 `end`를 "영업 종료 경계"로 볼지, "마지막 예약 가능 시간"으로 볼지?

**합의**:
- `end`는 점주가 마지막으로 예약을 받는 시간으로 입력/저장한다.
- 슬롯 생성 시 `end` 시간도 마지막 슬롯으로 포함한다. (inclusive)
- 예: 09:00~18:00, 30분 간격이면 마지막 슬롯은 18:00.

---

## 논의 13: 월 단위 캘린더 조회 응답

**질문**: 월 캘린더 화면에서 어떤 단위/형태로 데이터를 내려줄 것인가?

**합의**:
- 일 단위 슬롯 조회와 별도로 월 단위 조회 API를 둔다.
- 월 응답은 최소 아래 필드를 포함한다.
  - `availableDates`: 예약 가능한 dayOfMonth 목록
  - `holidayDates`: 휴무일 dayOfMonth 목록
  - `closedDates`: 운영시간 없음/직원 off dayOfMonth 목록
- 월 계산 시 `booking_window_days`, `min_booking_lead_minutes`, 서버 타임존 기준을 동일 적용한다.
