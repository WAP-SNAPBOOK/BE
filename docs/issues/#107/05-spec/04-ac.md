# `reservation` AC

작성일: `2026-03-10`

## 1. 예약 생성

- 고객이 유효한 슬롯에 대해 예약을 생성하면 `PENDING` 상태로 저장된다.
- 동일 슬롯에 기존 `PENDING`이 있어도 생성은 허용된다.
- availability 정책을 위반하면 생성이 거부된다.
- `requirements`는 저장된다.
- 메뉴와 입력값은 스냅샷으로 저장된다.

## 2. 예약 확정

- 점주만 확정할 수 있다.
- 자기 샵 예약만 확정할 수 있다.
- 확정 시 `durationMinutes`를 저장하고 점유 블록을 생성한다.
- 충돌 시 확정은 실패하고 기존 상태는 유지된다.

## 3. 예약 거절

- 점주만 거절할 수 있다.
- 자기 샵 예약만 거절할 수 있다.
- 성공 시 상태는 `REJECTED`다.

## 4. 예약 취소

- 고객과 점주 모두 취소할 수 있다.
- 고객은 예약일 전날 `23:59:59`까지 취소할 수 있다.
- 고객의 당일 셀프 취소는 실패한다.
- 점주의 운영상 취소는 가능하다.
- `CONFIRMED` 취소 시 점유 블록은 즉시 해제된다.
- `CANCELED`에는 취소 메타데이터가 저장된다.

## 5. 예약 수정

- 점주는 `date`, `time`, `staffId`, `requirements`, 이미지, 메뉴, 입력값을 수정할 수 있다.
- `CONFIRMED`에서 시간 관련 필드를 수정하면 점유를 다시 계산한다.
- 재계산 충돌 시 전체 변경은 실패하고 기존 상태를 유지한다.

## 6. 조회

- 목록 조회는 계속 제공된다.
- 상세 조회에는 `requirements`가 포함된다.
- 목록 조회에는 `requirements`가 포함되지 않는다.
- 상세 조회에는 메뉴 스냅샷과 입력값 스냅샷이 포함된다.

## 7. 에러 계약

- 상태 전이 실패는 액션별 `409` 에러 코드로 반환된다.
- 고객 취소 마감 위반은 `CUSTOMER_CANCELLATION_DEADLINE_PASSED`를 반환한다.
- availability 위반은 `400`, 점유 충돌은 `409`로 반환된다.
- 메뉴/입력값 검증 실패는 표준 비즈니스 에러 코드로 반환된다.
