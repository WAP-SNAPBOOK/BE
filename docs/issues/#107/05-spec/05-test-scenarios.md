# `reservation` 테스트 시나리오

작성일: `2026-03-10`

## 1. 예약 생성

- 유효한 슬롯으로 예약 생성 시 `PENDING` 생성
- 동일 슬롯에 기존 `PENDING`이 있어도 생성 성공
- 과거 날짜/시간 예약 생성 실패
- 예약 가능 기간 초과 예약 생성 실패
- 최소 리드타임 미달 예약 생성 실패
- 휴무일 예약 생성 실패
- 직원 운영시간 밖 예약 생성 실패
- 예약 불가 슬롯 예약 생성 실패
- `requirements` 저장 확인
- 메뉴 스냅샷 저장 확인
- 메뉴 입력값 스냅샷 저장 확인

## 2. 예약 확정

- 점주가 `PENDING` 예약 확정 성공
- 비점주 확정 실패
- 타 샵 점주 확정 실패
- `durationMinutes` 10분 단위 검증 실패
- 시간 블록 생성 확인
- 동일 직원 시간 블록 충돌 시 확정 실패 및 기존 상태 유지
- 이미 `CONFIRMED` 예약 재확정 실패
- `REJECTED` 예약 확정 실패
- `CANCELED` 예약 확정 실패

## 3. 예약 거절

- 점주가 `PENDING` 예약 거절 성공
- 비점주 거절 실패
- 타 샵 점주 거절 실패
- 이미 `CONFIRMED` 예약 거절 실패
- 이미 `REJECTED` 예약 재거절 실패
- `CANCELED` 예약 거절 실패

## 4. 예약 취소

- 고객이 전날 `23:59:59` 이전 취소 성공
- 고객이 예약일 `00:00` 이후 셀프 취소 실패
- 점주가 당일 운영상 취소 성공
- `CONFIRMED` 취소 시 점유 블록 해제 확인
- 취소 메타데이터 저장 확인
- 이미 `REJECTED` 예약 취소 실패
- 이미 `CANCELED` 예약 재취소 실패

## 5. 예약 수정

- 점주가 `PENDING` 예약의 `date/time/staffId` 수정 성공
- 점주가 `CONFIRMED` 예약의 `date/time/staffId` 수정 성공
- `CONFIRMED` 수정 시 점유 재생성 확인
- 점유 재생성 충돌 시 수정 실패 및 기존 상태/점유 유지
- 점주가 메뉴/입력값/`requirements`/이미지 수정 성공
- 비점주 수정 실패

## 6. 조회

- 상세 조회에 `requirements` 포함 확인
- 목록 조회에는 `requirements` 미포함 확인
- 상세 조회에 메뉴 스냅샷/입력값 스냅샷 포함 확인
- 권한 없는 상세 조회 실패
- 고객 목록 최신순 조회
- 점주 목록 최신순 조회

## 7. 메뉴/입력값 검증

- 다른 샵 메뉴 선택 실패
- 비활성 메뉴 선택 실패
- 정의되지 않은 입력 필드 실패
- 필수 입력값 누락 실패
- NUMBER 범위/step 위반 실패
- TEXT 최대 길이 위반 실패

## 8. API 정리

- `GET /api/reservations/shop/{shopId}/availability` 제거 확인
- 예약 가능 여부 테스트는 `availability` 도메인 API 기준으로 분리
