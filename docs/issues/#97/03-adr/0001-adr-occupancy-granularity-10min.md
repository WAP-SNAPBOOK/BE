## ADR-0001: 점유(겹침 방지) 최소 단위 = 10분

- 날짜: 2026-02-07
- 이슈: `#97`
- 상태: Accepted

---

## Context

- 현재 설계는 `ReservationTimeBlock` + UNIQUE(`staff_id`, `block_start_at`)로 **겹침 방지**를 DB 제약으로 고정하려는 방향이다.
- “원장이 예약 시간을 수정(reschedule)할 때 분 단위 제한을 완화”하려는 요구가 발생했으며,
  - 1분 단위 블록은 정확하지만 저장량이 증가한다.
  - 30분 단위 블록은 저장량은 적지만 임의 분(startAt)이 들어오면 정확한 점유 표현이 어렵다.
- 요구: **가장 작은 단위를 10분 단위 정도로** 하고 싶다.

---

## Decision

- 점유(겹침 방지) 최소 단위를 **10분**으로 한다.
- 따라서 “블록 모델을 유지”하는 대신, **확정/리스케줄의 입력도 10분 격자 정렬**이 필요하다.
  - `startAt`: 분(minute) % 10 == 0
  - `durationMinutes`: 10의 배수
- “원장이 임의 분(예: 14:07)까지 허용”이 반드시 필요하면, 이 ADR은 철회하고 **1분 단위 블록**으로 간다(정확도 우선).

---

## Consequences

- **정확도**
  - 10분 격자에 정렬된 예약은 블록 기반 점유로 정확하게 표현/차단 가능
  - 임의 분을 허용하면서 10분 블록으로만 겹침을 막는 것은 과점유/미점유(정책 불일치)를 유발하므로 채택하지 않는다.
- **성능/저장량**
  - 30분 대비 row 수는 대략 3배 증가
  - 1분 대비 row 수는 1/6 수준으로 감소
- **API 정책 변화**
  - 고객 예약 생성 time 30분 단위 정책은 유지할 수도 있으나(UX), 내부 점유 단위가 10분이면 “10분 단위로 완화”하는 선택지도 열림
  - 원장 reschedule은 “완전 자유 분”이 아니라 **10분 단위**로 허용하는 것이 일관적

---

## Plan.md 영향(수정 필요 항목)

- `1-D-3` (예약 생성 시 `time` 30분 단위)
  - (옵션) 유지: 고객은 30분 단위만 선택(UX 단순), 내부 점유는 10분(호환 가능)
  - (옵션) 완화: 고객도 10분 단위 선택 가능(더 유연)
- `1-F-1a` (확정 요청 `durationMinutes` 30분 단위)
  - **10분 단위 검증**으로 변경(10, 20, 30, ...)
- `1-F-4` (확정 시 `ReservationTimeBlock` 30분 단위 생성)
  - **10분 단위로 블록 생성**
- `1-F-6` (reschedule)
  - reschedule 입력 검증을 **10분 격자**로 명시

---

## Test Strategy (요약)

- DTO validation
  - `startAt`이 10분 단위가 아니면 400(또는 violation)
  - `durationMinutes`가 10의 배수가 아니면 400(또는 violation)
- 점유/겹침
  - 동일 staff + 동일 `block_start_at` 중복 저장 시 UNIQUE 위반
  - reschedule로 블록이 재생성될 때도 동일한 겹침 규칙이 유지됨
