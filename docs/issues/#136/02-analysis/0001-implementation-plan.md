# 채팅 재연결 메시지 복구

## 결론

웹소켓이 다시 연결되면 채팅방을 먼저 재구독하고 기존 메시지 조회 API로 최신 50개를 다시 받은 뒤, 화면에서 `messageId` 기준으로 중복을 제거한다.

`afterMessageId`와 별도의 `roomSequence`는 사용하지 않는다. 전역 메시지 ID에 다른 채팅방의 값이 끼어 있어도 최신 조회는 현재 채팅방으로 범위가 제한되므로 복구 결과에 영향을 주지 않는다.

## 용어

- 웹소켓 재연결: 연결이 끊긴 뒤 STOMP 클라이언트가 서버와 다시 연결된 상태다.
- 재구독: 다시 연결된 소켓에서 현재 채팅방의 메시지 주제를 다시 구독하는 작업이다.
- 최신 조회: `cursor` 없이 메시지 조회 API를 호출해 현재 채팅방의 최신 메시지를 받는 작업이다.
- 중복 제거: HTTP 조회와 웹소켓이 같은 메시지를 전달해도 `messageId`가 같으면 화면에 한 번만 표시하는 작업이다.

## 복구 흐름

1. 웹소켓 종료 또는 오류를 감지하면 화면에 재연결 상태를 표시한다.
2. STOMP 클라이언트가 5초 간격으로 자동 재연결을 시도한다.
3. 재연결에 성공하면 현재 채팅방을 먼저 재구독한다.
4. `GET /api/chat/rooms/{chatRoomId}/messages?size=50`으로 최신 메시지를 다시 조회한다.
5. 기존 조회 메시지와 실시간 메시지를 합치고 `messageId`로 중복을 제거한다.
6. 브라우저가 다시 포커스를 얻었을 때도 소켓이 연결돼 있으면 같은 최신 조회를 수행한다.

재구독을 먼저 하는 이유는 최신 조회가 진행되는 동안 새로 도착하는 메시지를 다시 놓치지 않기 위해서다. 조회와 웹소켓 양쪽에서 같은 메시지를 받는 것은 허용하고 화면에서 중복을 제거한다.

## 같은 채팅방의 저장 순서

메시지를 저장하기 전에 해당 `ChatRoom` 행을 비관적 쓰기 잠금으로 읽는다. 같은 채팅방에서 동시에 시작된 두 트랜잭션은 이 잠금을 차례대로 획득하므로 메시지 ID 할당과 커밋 순서가 같은 순서로 진행된다.

이 잠금은 다음 실패를 막는다.

1. 트랜잭션 A가 같은 방의 메시지 ID `100`을 할당받고 커밋을 지연한다.
2. 트랜잭션 B가 메시지 ID `101`을 먼저 커밋한다.
3. 클라이언트가 `101`을 본 뒤 `100`이 커밋되면 ID 이후 조회 방식에서는 `100`을 영구히 놓칠 수 있다.

방 행 잠금을 사용하면 B는 A가 커밋할 때까지 메시지를 저장하지 못하므로 이 역전이 발생하지 않는다. 다른 채팅방은 서로 다른 행을 잠그므로 전역적으로 모든 메시지를 직렬화하지 않는다.

## 사용하지 않는 방식

### `afterMessageId`

ID 이후 조회는 커서가 가리키는 메시지의 존재 확인과 역전 커밋 방어가 필요하다. 이번 복구 범위는 최근 누락이 50개보다 적다는 제품 가정을 사용하므로 기존 최신 조회로 충분하며 별도 API 계약을 유지하지 않는다.

### `roomSequence`

방별 연속 번호는 누락 범위를 정확히 표현할 수 있지만 컬럼, 유일 제약, 할당 로직과 마이그레이션이 추가된다. 최신 50개 재조회와 방 행 잠금으로 현재 문제를 해결할 수 있어 적용하지 않는다.

## 보장 범위와 한계

- 예약 처리 과정에서 저장한 시스템 메시지는 예약 트랜잭션에 함께 저장하고, 커밋된 뒤 웹소켓으로 발행한다.
- 웹소켓 발행을 놓쳐도 재연결 후 최신 50개 조회로 최근 메시지를 복구한다.
- 같은 메시지를 HTTP와 웹소켓에서 모두 받아도 한 번만 표시한다.
- 연결이 끊긴 동안 현재 채팅방에 메시지가 50개를 초과해 쌓이는 경우에는 가장 최신 50개보다 오래된 누락분까지 자동 복구한다고 보장하지 않는다. 현재 사용 시나리오에서는 이 가능성을 수용한다.

## 검증 항목

- 재연결 성공 시 재구독 이후 메시지 조회가 실행되는지 확인한다.
- 최신 조회와 실시간 수신이 겹쳐도 메시지가 중복 표시되지 않는지 확인한다.
- 시스템 메시지의 발신자 이름이 최신 조회에서도 유지되는지 확인한다.
- 오래된 읽음 메시지 ID가 최신 읽음 상태를 뒤로 되돌리지 않는지 확인한다.
- 동일 채팅방의 동시 메시지 저장이 방 행 잠금으로 직렬화되는지 확인한다.
