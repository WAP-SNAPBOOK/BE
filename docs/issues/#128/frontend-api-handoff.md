# `#128` 점주 캘린더 프론트 전달 문서

작성일: `2026-06-17`

## 범위

이 문서는 점주/직원용 예약 관리 캘린더의 제품 결정사항과 조회 API 계약을 정리한다.  
이번 이슈 `#128`은 캘린더 조회만 포함한다. 예약 확정/수정/거절/취소와 변경 이력/자동 메시지는 후속 이슈에서 다룬다.

## 핵심 결정사항

### 사용자와 목적

- 이 캘린더는 고객용 예약 날짜 선택 화면이 아니다.
- 점주/직원용 예약 관리 화면이다.
- 현재 백엔드에서 `Staff`는 로그인 주체가 아니라 매장 내부 리소스다.
- 초기 API는 점주 인증 사용자 전용으로 제공한다.
- 직원 계정/직원 권한은 후속 확장 가능성으로만 둔다.

### 화면 구조

- 상단은 일요일 시작 7일 날짜 스트립이다.
- 본문은 선택한 하루의 타임라인이다.
- 첫 진입은 전체 직원 보기다.
- 월 이동은 좌우 화살표로 처리한다.
- 월 이동 시 선택 날짜는 같은 일자를 유지하고, 없는 날짜는 해당 월 말일로 보정한다.
  - 예: `1월 31일`에서 다음 달 이동 시 `2월 28일` 또는 윤년 `2월 29일`
- 월 표시를 눌러 월간 캘린더를 여는 기능은 초기 범위에 포함하지 않는다.

### 날짜 스트립

- 날짜 스트립은 현재 화면 범위 기준으로 예약 배지를 표시한다.
- 전체 보기에서는 모든 활성 직원 예약과 미지정 예약을 포함한다.
- 특정 직원 보기에서는 해당 직원 예약만 포함한다.
- `PENDING` 예약이 있으면 대기 표시를 우선한다.
- `PENDING`이 없고 `CONFIRMED`만 있으면 예약 있음 표시를 한다.
- `CANCELED`, `REJECTED`는 날짜 스트립 배지 계산에서 제외한다.

### 직원 컬럼

- 전체 보기에서는 활성 직원 전체를 컬럼으로 표시한다.
- 직원 컬럼이 많으면 가로 스크롤로 처리한다.
- 시간축은 좌측 고정, 직원 헤더는 상단 고정을 권장한다.
- 특정 `staffId` 필터를 사용하면 해당 직원 1개 컬럼만 표시한다.
- 직원별 근무 불가 구간은 각 직원 컬럼 내부에서 비활성 배경으로 표시한다.

### 미지정 컬럼

- `staffId == null`이거나 직원 매칭에 실패한 예약은 `미지정` 컬럼에 모은다.
- `미지정` 컬럼은 전체 보기에서만 표시한다.
- `미지정` 컬럼은 맨 오른쪽 끝에 둔다.
- 미지정 예약이 없으면 `미지정` 컬럼은 표시하지 않는다.
- 특정 직원 필터 상태에서는 `미지정` 컬럼을 제외한다.

### 시간축과 운영시간

- 선택일의 매장 운영시간 기준으로 시간축을 만든다.
- 매장 영업 전/후 시간은 기본적으로 표시하지 않는다.
- 운영시간 중간 공백은 비활성 구간으로 표시한다.
- 전체 보기의 시간축은 매장 운영시간 기준이다.
- 직원별 근무 가능/불가 여부는 각 직원 컬럼 내부에서 표현한다.
- 시간축은 1시간 라벨과 30분 보조선을 권장한다.
- 휴무일 또는 운영시간 없는 날에도 예약이 있으면 예약은 표시한다.
- 휴무일 또는 운영시간 없는 날에 예약이 없으면 휴무/빈 상태로 표시한다.
- 휴무일 또는 운영시간 없는 날에 예약이 있으면 예약 범위에 앞뒤 30분 여백을 둔 시간축을 사용한다.

### 예약 표시

- 기본 캘린더에는 `PENDING`, `CONFIRMED` 예약만 표시한다.
- `CANCELED`, `REJECTED` 예약은 기본 캘린더에서 숨긴다.
- `PENDING`과 `CONFIRMED`를 모두 표시한다.
- `PENDING` 예약은 같은 시간대에 여러 개 겹칠 수 있다.
- 겹치는 예약은 같은 컬럼 안에서 겹침 레이아웃으로 표시한다.
- 예약 블록에는 고객명, 시간, 대표 메뉴명, 상태 라벨을 표시한다.
- 상태 라벨은 `대기`, `확정`을 표시한다.
- 메뉴가 여러 개면 첫 번째 메뉴명과 `외 N개` 형식으로 표시한다.
- 예약 블록에는 가격을 표시하지 않는다.
- 가격은 상세 바텀시트에서만 표시한다.

### 예약 블록 높이

- 예약 블록 높이는 표시 소요시간에 비례한다.
- `PENDING` 예약 블록은 초기 30분 고정이다.
- `PENDING` 블록에는 별도 `예상` 표시는 하지 않고 `대기` 라벨만 표시한다.
- `CONFIRMED` 예약 블록은 `durationMinutes`에 비례한다.

### 상세 바텀시트

- 예약 블록을 누르면 예약 상세 바텀시트를 연다.
- 캘린더 조회 응답은 요약 정보만 제공한다.
- 상세 바텀시트는 예약 상세 API를 별도로 호출해 구성한다.
- 상세 바텀시트에는 고객명, 고객 연락처, 예약 상태, 시간, 소요시간, 담당 직원, 요청사항, 사진, 선택 메뉴, 메뉴별 가격, 총액을 보여주는 방향이다.
- 사진은 상세 바텀시트에서만 썸네일로 표시한다.
- 썸네일 클릭 시 전체 보기를 제공하는 방향이다.
- 사진이 없으면 사진 영역은 숨긴다.
- 변경 이력은 기본 캘린더 응답에 포함하지 않고, 상세에서 `변경 이력 보기` 버튼으로 접근한다.

### 가격 표시

- 메뉴별 가격은 `priceSnapshot` 기준으로 표시한다.
- 가격 있는 메뉴만 합산한다.
- 가격 없는 메뉴는 `가격 미정`으로 표시한다.
- 일부 메뉴만 가격이 없으면 총액 옆에 `일부 메뉴 가격 미정`을 표시한다.
- 모든 메뉴 가격이 없으면 `총액 미정`으로 표시한다.

### 예약 액션 후속 정책

아래 항목은 `#128` 구현 범위가 아니지만, 프론트 플로우 설계 시 참고한다.

- `PENDING` 예약은 확정/거절 가능해야 한다.
- `PENDING` 확정 시 담당 직원 선택/변경, 시작 시간 변경, 소요시간 입력/수정이 가능해야 한다.
- `미지정` 예약은 확정 전에 담당 직원 선택이 필수다.
- `CONFIRMED` 예약은 수정/취소 가능해야 한다.
- `CONFIRMED` 수정 가능 항목은 시작 시간, 소요시간, 담당 직원, 점주 전달 메시지다.
- 거절/취소 사유는 필수다.
- 과거 예약도 확정/수정/거절/취소 가능해야 한다.
- 과거 예약 변경에도 고객 자동 메시지를 발송한다.
- 빈 시간대를 눌러 신규 예약을 만드는 기능은 초기 범위에서 제외한다.

### 시간 선택 후속 정책

- 확정 폼 기본 소요시간은 30분이다.
- 예약 시작 시간 선택/수정은 30분 단위다.
- 예약 소요시간 선택/수정은 30분 단위다.
- 최대 소요시간은 180분이다.
- 백엔드가 더 작은 단위를 허용하더라도, 이 캘린더 UI에서는 30분 단위로 통일한다.

### 자동 메시지 후속 정책

- 자동 채팅 메시지는 확정/수정/거절/취소 이벤트에서 발송한다.
- 예약 수정 메시지는 변경된 항목과 최종 예약 요약을 함께 표시한다.
- 확정/수정 시 점주가 추가 전달 메시지를 입력할 수 있어야 한다.
- 거절/취소 시 사유를 고객에게 안내한다.

### 충돌 처리 후속 정책

- 확정/수정 시 `staffId + startAt + durationMinutes` 기준으로 충돌을 검사한다.
- 충돌 시 액션은 실패한다.
- 프론트 메시지는 `해당 담당자의 선택 시간대에 이미 예약이 있습니다.` 수준의 간단한 문구를 사용한다.

## 화면 정책

위 결정사항을 기준으로 `#128`에서는 조회 응답만 제공한다.  
프론트는 캘린더 조회 응답으로 날짜 스트립과 선택일 타임라인을 렌더링하고, 예약 블록 클릭 시 예약 상세 API를 별도로 호출한다.

## API

```http
GET /api/owner/shops/{shopId}/calendar?date=2026-11-05&staffId=1
Authorization: Bearer {accessToken}
```

### Path

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `shopId` | Long | Y | 캘린더를 조회할 매장 ID |

### Query

| 이름 | 타입 | 필수 | 설명 |
| --- | --- | --- | --- |
| `date` | `yyyy-MM-dd` | N | 선택 날짜. 미전달 시 서버 기준 오늘 |
| `staffId` | Long | N | 특정 직원 필터. 미전달 시 전체 직원 보기 |

## Field Notes

| 필드 | 설명 |
| --- | --- |
| `days[].hasPending` | 해당 날짜에 `PENDING` 예약이 1개 이상 있으면 `true` |
| `days[].hasConfirmed` | 해당 날짜에 `CONFIRMED` 예약이 1개 이상 있으면 `true` |
| `timeline.startTime/endTime` | 선택일 타임라인 표시 범위 |
| `staffColumns[].workingRanges` | 해당 직원의 근무 가능 구간 |
| `staffColumns[].unavailableRanges` | 타임라인 범위 안에서 직원 근무 가능 구간이 아닌 구간 |
| `reservations[].durationMinutes` | 실제 예약 소요시간. `PENDING`은 `null`일 수 있음 |
| `reservations[].displayDurationMinutes` | 캘린더 블록 표시용 소요시간. `PENDING`은 30분 고정 |
| `reservations[].menuSummary` | 예약 블록에 표시할 대표 메뉴 문자열 |

## 휴무일/운영시간 없는 날

- 휴무일이고 예약이 없으면 `staffColumns`는 빈 배열일 수 있다.
- 휴무일이거나 운영시간이 없어도 예약이 있으면 예약은 표시한다.
- 운영시간 기준을 잡을 수 없고 예약이 있으면 `startTime/endTime`은 예약 범위에 앞뒤 30분 여백을 둔다.

## 상세 바텀시트

캘린더 응답은 요약 정보만 제공한다.  
예약 블록을 누르면 기존 예약 상세 API를 호출해 상세 바텀시트를 구성한다.

```http
GET /api/reservations/{reservationId}
```

상세 바텀시트에는 후속 이슈에서 메뉴별 가격, 총액, 사진, 요청사항, 변경 이력 보기 등을 보강한다.
