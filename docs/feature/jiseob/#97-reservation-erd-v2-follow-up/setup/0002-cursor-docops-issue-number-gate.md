# Cursor DocOps 개선: 이슈 번호 게이트 + 이슈 기반 폴더 구조

- 작성일(런타임): 2026-01-26
- 대상 브랜치: `feature/jiseob/#97-reservation-erd-v2-follow-up`

## 1) 어떻게 변경할지(설계/접근 방식)
### 1.1 요구사항
- 작업 시작 시 사용자가 **이슈 번호**를 제공해야 한다.
- 이슈 번호가 없으면, AI는 **반드시 이슈 번호를 요구**한다(문서 생성/코드 변경 진행 금지).
- 문서 저장 경로는 **이슈 번호 단일 루트**를 사용한다(브랜치명 비의존).

### 1.2 경로 규칙(새 기준)
- 기본 루트: `docs/issues/#<issue-number>/`
- 이슈 루트 아래 구조(기존 DocOps 게이트를 그대로 이식):
  - `00-intake/`
  - `01-issue/`
  - `02-analysis/`
  - `03-decisions/`
  - `04-tdd/`
  - `05-green-design/`
  - `06-implementation/`
  - `07-pr/`
  - `99-learning/`

### 1.3 rules 변경(요지)
- `10-docops-workflow.mdc` 또는 신규 rules 파일에 다음을 추가한다.
  - **Issue number gate**: 이슈 번호 미제공 시 반드시 요청
  - 이슈 번호를 받으면 그 값을 `<issue-number>`로 간주하고, 문서 생성/스킬 출력 경로는 위 루트를 사용

### 1.4 skills 변경(요지)
- 기존 skills의 Output 경로를 모두 아래 형태로 변경한다.
  - 예: `docs/issues/#<issue-number>/04-tdd/plan.md`
- Skills는 여전히 “문서 생성/수정까지만” 수행한다(커밋/푸시/PR 생성 금지).

## 2) 변경 근거(이유, 장단점)
### 2.1 이유
- “작업 단위(이슈)”가 폴더의 최상위로 명확히 드러나면,
  - 문서 탐색/정렬이 쉬워지고
  - 작업 시작 시 컨텍스트(이슈 번호) 누락을 시스템적으로 방지할 수 있다.

### 2.2 장점
- “이슈 번호 없는 작업”이 원천적으로 줄어듦(게이트)
- 문서가 이슈 단위로 깔끔하게 정리됨

### 2.3 단점/주의
- 이슈 번호를 항상 입력해야 하므로 초기 입력 비용이 늘어남(의도된 트레이드오프)
- 기존에 이슈 루트 없이 작성된 문서들은 새 규칙과 경로가 달라질 수 있음(마이그레이션은 이번 범위에서 제외)

## 3) 코드 수정 예시(diff 또는 예시 코드)
### 3.1 변경 전/후 Output 예시
- 변경 전: `docs/<type>/<owner>/<branch-name>/04-tdd/plan.md` (기존)
- 변경 후: `docs/issues/#<issue-number>/04-tdd/plan.md`

## 4) 변경 후 예상 결과(동작, 영향 범위)
- 작업을 시작할 때:
  - 이슈 번호가 없으면 AI가 반드시 요구하고, 제공되기 전까지 문서/코드 작업을 진행하지 않는다.
- 이슈 번호를 받으면:
  - 모든 문서/스킬 산출물이 `issues/#<issue-number>/...` 아래로 생성된다.

## 5) 실행 절차(동의 후 수행)
1) `.cursor/rules`에 이슈 번호 게이트 규칙 추가(또는 기존 rules 보강)
2) `.cursor/skills` 10개 Output 경로를 `issues/#<issue-number>/...`로 통일
3) 변경사항 커밋/푸시(현재 브랜치)
